Data & Schema Decisions
DR-001 No PII Storage
Email and name are NOT stored in member_identity. They are re-fetched from Wix on-demand at reconciliation time. Protects AccessSync from being a data liability. Email never hits the AccessSync database.
Locked Schema Legal ⛔ Do not revisit
DR-003 source_tag = 'accesssync'
All users provisioned by AccessSync carry source_tag='accesssync'. This is the reconciliation scope boundary — only these users are touched during sweeps. Manual Kisi users are never affected.
Locked Schema
DR-004 member_access_log — lifecycle only
member_access_log is a lifecycle table, not an operational noise log. Only meaningful state transitions are recorded: provisioned, disabled, restored, revoked, failed. Not every queue job or retry.
Locked Schema
DR-013 member_identity A/B pattern
Platform-agnostic A/B schema concept — identity stored as platform_member_id + source_platform (not separate tables per platform). Column names updated by DR-021. A/B concept preserved.

DR-018 last_sync_at on clients table
Single timestamp column on clients table. Not a separate sync_state table. V1 only needs one timestamp per client. Separate table deferred to V2 if sync history reporting is needed.

DR-019 adapter_admin_log — configured_by + configured_at
Two nullable columns added to adapter_admin_log: configured_by (VARCHAR 255) and configured_at (TIMESTAMPTZ). Nullable preserves existing rows. Populates when operator self-service UI is built.

DR-021 Platform-agnostic member_identity
wix_member_id → platform_member_id. New column: source_platform VARCHAR(50) DEFAULT 'wix'. UNIQUE: (client_id, source_platform, platform_member_id). Normalized event: platformMemberId + sourcePlatform. Enables Squarespace with zero schema changes.

DR-024 client_activity_summary — Layer 3 daily UPSERT
Standard Adapter Layer owns daily activity aggregation. UNIQUE(client_id, summary_date). Fault-tolerant — failures logged but never block grant/revoke path. Counters: events_received, grants_completed, revokes_completed, errors_count.

DR-027 Per-location subscription model
AccessSync charges one subscription per physical location (AccessSync pricing decision, not a Kisi constraint). locations gets: subscription_status (default 'inactive'), tier, subscribed_at, subscription_id. Provisioning gated on subscription_status='active'.
Locked Schema Product
DR-028 hardware_api_key — AES-256-GCM encrypted
clients.hardware_api_key (org default) + locations.hardware_api_key (nullable override). Lookup: location key || client key. AES-256-GCM via crypto-utils.js + KISI_ENCRYPTION_KEY env var. Never store plaintext in DB.
Locked Schema Security ⛔ Do not revisit
DR-029 Sub-member ID format
{wix_uuid}###as{NNN} (e.g. a1b2c3d4###as001). Deterministic, collision-free, reversible to plan holder. ###as delimiter chosen for zero natural occurrence in UUIDs. Counter NNN zero-padded, scoped per plan holder.
Locked Schema
DR-030 plan_holder_id column
Added to member_identity and member_access_state. Links sub-members to the primary Wix member who owns the family plan. NULL for single-plan and event-booking members.
Locked Schema
DR-034 member_access_sources — multi-source grant/revoke
Tracks why a member is in a Kisi group (plan, booking, family_plan). Pre-grant check prevents overwriting permanent access with time-limited bookings. Revoke only fires Kisi DELETE when all sources are gone.

Architecture Decisions
DR-002 Access Adapter Layer — bidirectional identity bridge
The Access Adapter Layer is the bidirectional identity bridge between platform member IDs (Wix) and hardware user IDs (Kisi). It is the only layer that maps between the two identity spaces.
Locked Architecture
DR-010 Idempotency via processed_event_ids
Every Wix event ID is stored in processed_event_ids before processing. webhook-processor.js checks before enqueuing. Duplicate events are silently dropped — no double-provisioning or double-revocation.
Locked Architecture Infrastructure ⛔ Do not revisit
DR-011 in_flight status lock
member_access_state.status = 'in_flight' is the concurrency lock. If set, concurrent grant/revoke for the same member is rejected with an error. Lock is acquired atomically in resolveAndLock() and released in completeGrant/Revoke/releaseLock().
Locked Architecture ⛔ Do not revisit
DR-022 7-layer architecture
L1 Wix Connector → L2 Wix Adapter → L3 Standard Adapter → L4 Core Engine → L5 Hardware Standard Adapter → L6 Kisi Adapter → L7 Kisi Connector. Backward-compat shims at adapters/wix-adapter.js, kisi-adapter.js, seam-adapter.js. Do not collapse layers.
Locked Architecture ⛔ Do not revisit
DR-023 Layer 3 exclusively owns identity + state writes
Standard Adapter Layer (Layer 3) is the sole writer of member_identity, member_access_state, and the in_flight lock. Core Engine (Layer 4) never writes these tables directly. Enforces ownership boundary — critical for correctness.
Locked Architecture ⛔ Do not revisit
DR-031 Family plan — upstream explosion in Layer 2
plan_members webhook events are exploded into synthetic single-member events before entering processEvent. Core Engine grant/revoke path is unchanged. Explosion happens in Wix Adapter (Layer 2) — Core Engine never sees family-plan-specific logic.
Locked Architecture
Infrastructure Decisions
DR-001 Railway as hosting platform
Core Engine and Admin Hub both hosted on Railway. Entry: node server.js and node admin/server.js. Crons managed as Railway Cron services. Redis for BullMQ also on Railway.
Locked Infrastructure
DR-009 HMAC-SHA256 on all Wix webhooks
Every inbound Wix webhook is verified with HMAC-SHA256 before processing. wix-connector.js (Layer 1) rejects unverified requests. hmac-monitor.js (Sprint 5.1) alerts on spikes. WIX_WEBHOOK_SECRET env var required.
Locked Security ⛔ Do not revisit
DR-012 BullMQ queue on Railway Redis
Core Engine uses BullMQ + Railway Redis for the job queue. webhook-processor.js enqueues. queue-worker.js coordinates with concurrency 20. Crons: reconciliation.js (nightly) + hardware-health-check.js (every 6 hours).
Locked Infrastructure
Product Decisions
DR-005 Kisi lockdown override — skip, not fail
During a Kisi lockdown event, access provisioning actions skip (not fail) processing. Events are not dead-lettered. Lockdown is a temporary state — skipping preserves queue health.
Locked Product
DR-006 Member sync screen — one-time post-purchase
The member-facing sync status screen is a one-time post-purchase UI. Shown after Wix checkout completes. Not a persistent dashboard. 4 states: syncing, active, error, pending. Polls every 3s up to 60 polls.
Locked Product UI
DR-007 Kisi managed users — send_emails: false
All AccessSync-provisioned Kisi users are created as managed users with send_emails: false. HOG exception: DR-017 (regular users). DR-007 active for all other clients.
Locked Product
DR-008 Pricing — $30 / $60 / $150 per location
AccessSync pricing tiers: Base $30/mo/location, Pro $60/mo/location, Connect $150/mo/location. Tier names: Base, Pro, Connect. Infrastructure cost $35/mo fixed. ~99% margin at scale. Do not change without SAGE.
Locked Product ⛔ Do not revisit
DR-011 Kisi routes direct API — not through Seam
Kisi integration uses Kisi's direct REST API. Not routed through Seam. Seam is a separate adapter stub for future use. kisi-adapter.js (L6) and kisi-connector.js (L7) handle all Kisi calls directly.

House of Gains Phase 1 uses Velo direct install (not Wix App Market packaging). Member sync screen and events.js installed directly into the HOG Wix site. App Market packaging deferred post-V1.

DR-017 HOG exception — regular users (not managed)
House of Gains uses regular Kisi users (Terminal Pro pattern), not managed users. DR-007 (managed users) remains active for all other clients. HOG exception is scoped to Phase 1 only.
Locked Product
DR-020 Operator email via Resend SDK
Operator notifications use Resend SDK from Core Engine (Railway). clients.notification_email is the per-tenant destination. ACCESSSYNC_OWNER_NOTIFICATION_EMAIL env var is the platform-level fallback (Daxx's email). No Wix dependency for email delivery.
Locked Product Infrastructure
DR-032 Family plan — draft→submit workflow
Operator adds sub-members in draft state, reviews, then submits batch. No access provisioned until submit. Prevents partial-state errors from incremental adds. Draft state is local only — no DB writes until submit.
Locked Product UI
DR-033 Unified member access widget — 3 modes
Single HTML screen handles three modes via planType param: 'plan' (single), 'event' (booking), 'family'. planType controls visibility of family-specific UI (member list, add section, submit bar, counter). One screen, not three.
