AccessSync — Grant Flow

Full decision path from webhook receipt to Kisi group assignment · queue-worker → grant-revoke → kisi-adapter

Entry
Webhook received L1 wix-connector
HMAC verified → parseEvent() → standard event object → dedup check → BullMQ grant job enqueued
Event type branch L4 queue-worker
Three fast-exit paths before the main grant sequence runs
payment.recovered → enableAccess only, no new role
plan.started → skip to identity resolve (user already exists)
everything else → main grant sequence ↓
Step 1 — Plan Mapping
Resolve plan mappings L4 plan-mapping-resolver
source_plan_id → all active mappings[] with hardwareGroupId, apiKey, accessType
null → plan unknown → error_queue + operator alert → exit
[] empty → plan mapped but no group yet → park pending_hardware → exit
mappings[] returned → continue ↓
Step 2 — Identity & Lock
resolveAndLock() L3 standard-adapter DB
UPSERT member_identity → check member_access_state → set status = in_flight (atomic transaction)
in_flight already set → IN_FLIGHT_LOCK → BullMQ retries → exit
lock acquired → memberId returned → continue ↓
Step 3 — Hardware API Key
Fetch + decrypt API key L4 queue-worker DB
Client-level hardware_api_key — AES-256-GCM decrypt (DR-028)
no key → park pending_hardware → exit
key present → continue ↓
Step 4 — Kisi User Identity
resolveIdentity() L3 standard-adapter
DB cache check first — if hardware_user_id already stored, return immediately
GET /users?query=email Kisi API
Find existing Kisi user by email
found → return kisiUserId → skip createUser
not found → POST /users ↓
POST /users Kisi API
{ email, name, send_emails: true, confirm: true } — pattern per clients.kisi_user_pattern (DR-043)
HOG default: invited → send_emails: true
Email missing? Gate 2 recovery OB-89
Ladder: Wix Members API lookup → DB cache → park pending_identity
email unrecoverable → park pending_identity → exit
hardwareUserId resolved → continue ↓
Step 4.5 — Delayed Start Check
startDate in future? L4 queue-worker
If plan startDate > now + 60s — user created in Kisi, group assignment deferred
future start → park pending_start → wait for orderStarted event → exit
start now → continue ↓
Step 5 — Hardware Grant Loop
For each mapping in mappings[] — one iteration per Kisi group
Source check (OB-47 / DR-034) DB
Query member_access_sources JOIN member_role_assignments for existing permanent row on this group
permanent row exists → reuse prior roleAssignmentId → skip hardware call → record source row only
no prior source → check member_role_assignments ↓
Existing role assignment check DB
Query member_role_assignments for prior role assignment on this (member_id, hardware_group_id)
found (retry or shared group) → reuse roleAssignmentId → skip hardware call
none found → POST /role_assignments ↓
POST /role_assignments Kisi API
{ user_id, role_id: "group_basic", group_id } + optional valid_until for time-limited access
200 → roleAssignmentId stored → newHardwareCallMade = true
409 conflict → fetch existing roleAssignmentId → idempotent success
404 group not found → flag group health_status = not_found → config_alert_log → continue loop (other groups still run)
4xx other → UnrecoverableError → dead-letter immediately
429 / 5xx → retry with backoff (up to 3×) → BullMQ retry queue
All groups failed?
If every group in the loop errored and assignments[] is empty
all failed → throw first error → retry engine → error_queue + operator alert
at least one succeeded → partial or full success → continue ↓
Step 6 — Record Success
completeGrant() L3 standard-adapter DB
For each assignment:
· UPSERT member_role_assignments (ON CONFLICT updates billing_snapshot)
· INSERT member_access_sources (ON CONFLICT DO NOTHING — idempotent)
· UPDATE member_access_state → status = active
Write member_access_log?
Only when newHardwareCallMade = true — prevents duplicate provisioned entries from Wix triple-fire purchase events
all assignments reused → log skipped (grant.log.skipped_duplicate)
real hardware call made → INSERT member_access_log event = 'provisioned'
Terminal
Grant complete
Member is active in Kisi group · member_access_state.status = active · role assignment ID stored
First grant: welcome email fired via Resend (clients.first_grant_sent atomic flag)
