Operator Onboarding Flow

How AccessSync identifies, authenticates, and onboards operators via the Wix Dashboard Page Extension.

PROPOSED — not yet built

Path A — Returning Operator

instanceId matches an existing client. Operator token issued immediately. Redirected to dashboard. Zero friction.

Path B — Known Site, New Instance

instanceId not found, but siteId matches. Occurs on reinstall or first portal load after manual onboarding. wix_instance_id updated silently. Operator never sees onboarding.

Path C — New Client

Neither instanceId nor siteId matches. Operator goes through the 5-step onboarding wizard. Client row created with both identifiers. Token issued on completion.

Known Failure Modes — FAULT

  • authorizationCode absent or expired — Path B has no siteId source. Falls through to Path C. Operator re-onboards. Upsert on site_id prevents duplicate if siteId becomes available later. If siteId is never available, a duplicate client row may be created.
  • Reinstall on a different Wix site — Both instanceId and siteId change. Neither lookup hits. Path C creates a second client row. Recovery requires admin merge or manual DB fix. No automated recovery path exists yet.
  • Onboarding abandonment mid-flow — Client row not created. Next portal load restarts from Path C. No partial state persisted. Acceptable behavior — wizard must not show stale pre-filled data from a prior abandoned session.
  • Concurrent onboarding sessions — Two tabs reach Step 5 simultaneously. ON CONFLICT (site_id) DO UPDATE is atomic — second write updates, does not duplicate. Requires site_id UNIQUE NOT NULL constraint at DB level.

Open Questions — PARSE Verification Pending

authorizationCode reliability: Path B depends on Wix always passing authorizationCode as a URL parameter when loading the Dashboard Page Extension iframe. This was observed in one log on 2026-04-09 but has not been verified as a documented, stable Wix behavior. PARSE must confirm before Path B middleware is built.

instanceId stability: The Wix signed instance instanceId is assumed to be stable for the lifetime of an app installation. If it rotates on session or on re-authentication, Path A breaks silently. PARSE to verify.
