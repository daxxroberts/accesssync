AccessSync — Data Model

Database Schema

14 PostgreSQL tables. Column-level detail, layer ownership, and the DR that created each table. Source of truth: schema.sql + migrations/dr-035.sql for live column names.
Schema note (DR-035): schema.sql is the baseline and still shows kisi_api_key and wix_plan_id. The Railway DB has hardware_api_key and source_plan_id after migrations/dr-035.sql runs. This page documents the live state (post-migration). Run dr-035.sql before deploying Sprint 5 code.
Foundation — Core Operational Tables
clients
Tenants. One row per AccessSync customer (gym operator). Stores org-level hardware API key (encrypted), notification email, billing tier.

Access Adapter Layer — Identity & State (Layer 3 Owned)
member_identity
Platform-agnostic identity bridge (DR-021). Maps Wix member ID → hardware user ID. No email/name stored — data minimization (DR-001). source_tag='accesssync' distinguishes managed users (DR-003). Standard Adapter (Layer 3) exclusively owns writes (DR-023).
Layer 3 DR-001 DR-003 DR-021 DR-023
ColumnTypeNotes
id PKUUID
client_id FKUUID→ clients(id) ON DELETE CASCADE
platform_member_idVARCHAR(255)DR-021: was wix_member_id. Platform-agnostic member identifier from the source platform.
source_platformVARCHAR(50)DR-021: 'wix', 'squarespace', etc. DEFAULT 'wix'
hardware_platformVARCHAR(50)'kisi', 'seam' — which hardware system this member is provisioned in
hardware_user_idVARCHAR(255)The generated ID in Kisi/Seam. NULL until resolved by resolveIdentity().

created_at / updated_atTIMESTAMPTZUNIQUE(client_id, source_platform, platform_member_id)
member_access_state
Provisioning status per member. in_flight status is the concurrency lock (DR-011). Standard Adapter (Layer 3) exclusively owns all status writes (DR-023). UNIQUE on member_id — one state row per member.

member_role_assignments
Multi-door grant storage (DR-026). One row per hardware role assignment per member per plan mapping. UNIQUE(member_id, mapping_id) enforces idempotency. completeRevoke() deletes all rows atomically. Standard Adapter (Layer 3) owns writes.

Activity / Telemetry
client_activity_summary
Daily aggregated event counts per client (DR-024). UPSERT pattern — Standard Adapter (Layer 3) increments on every event. Fault-tolerant writes — failures logged but never block grant/revoke path. UNIQUE(client_id, summary_date).
Layer 3 DR-024
ColumnTypeNotes
id PKUUID
client_id FKUUID→ clients(id). UNIQUE with summary_date.
summary_dateDATECURRENT_DATE — one row per client per day
events_receivedINTEGERDEFAULT 0. Incremented on resolveAndLock().
grants_completedINTEGERDEFAULT 0. Incremented on completeGrant().
revokes_completedINTEGERDEFAULT 0. Incremented on completeRevoke().
errors_countINTEGERDEFAULT 0. Incremented on releaseLock() (error path).
updated_atTIMESTAMPTZDEFAULT CURRENT_TIMESTAMP
config_alert_log
Operator configuration issue tracking. Fires when plan mappings have problems: missing door, missing group, expired credentials, location mismatch. Deduplicates via last_seen_at.

Observability
webhook_log
Every inbound Wix webhook. Written by wix-connector.js (Layer 1) before processing. Admin Hub Webhook Inspector reads this table. hmac_status + dedup_status support HMAC spike alerting (Sprint 5.1).
