What Breaks a Real Customer Today
Path A — #1 Blocker
Location never activates → zero members provision
Onboarding completes → subscription_status = 'inactive' → DR-027 blocks plan-mapping-resolver → no grant/revoke jobs ever fire. The system looks complete but does nothing.
OB-44 · OB-45
Path A — Plan Mapping
Kisi group dropdown is empty → can't map plans
After connecting Kisi, operator goes to plan mapping and sees an empty dropdown. GET /groups is never called. getGroups() method doesn't exist yet. Mapping is impossible.
OB-42 · OB-47
Path A — Onboarding Step 5
Webhook secret never mentioned → every webhook fails HMAC
events.js requires accesssync_webhook_secret in Wix Secrets Manager. Onboarding never tells the operator to add it. Every webhook sent fails signature verification silently.
OB-41
Path B — Member UX
No post-purchase page → member has zero feedback
Member completes checkout → sees Wix order confirmation → no AccessSync context → shows up at gym → door doesn't open (if provisioning is slow) → calls the gym. Bad first impression on every new signup.
OB-46
Path B — Webhook Pipeline
events.js field paths unverified against live Wix API
The Velo events.js extracts memberId, planId, etc. from webhook payloads. These paths have never been confirmed against a live Wix event. If any path is wrong, that event type silently drops all members.
P6
Path C — Console
All 6 console pages show mock data
Dashboard, Members, Plan Mapping, Access, Locations, Admin Panel all render static fake data. Operators see a working-looking UI but none of it reflects their actual members, errors, or access events.

Sprint Plan
1
Make the System Actually Work
Goal: A real operator can complete onboarding and have provisioning fire for a real member
Path A · Critical path
OB-44 + OB-45
Location Activation on Onboarding Complete
When owner bypass PIN is used OR when a payment is confirmed, auto-set subscription_status = 'active'. Without this, provisioning never fires. Wire bypass to also call the activate endpoint. This is the single most important item in the entire backlog.
NOVA
OB-42
Kisi Groups Discovery After Key Validation
After API key is saved, call GET /groups (full list), show operator a summary of what AccessSync found. Warn if zero groups. Builds kisi-adapter.getGroups() + GET /operator/clients/:id/kisi-groups endpoint. This also feeds OB-47 (plan mapping dropdown).
NOVA
OB-47
Plan Mapping Screen — Live Kisi Groups Dropdown
Wire the /plan-mapping EJS page's group dropdown to GET /operator/clients/:id/kisi-groups. Currently shows nothing. Once OB-42 builds the endpoint, this wires the UI to it. Operators can now actually map plans to doors.
NOVA + FORGE
OB-41 (partial)
Webhook Secret Setup Instructions in Onboarding Step 5
Add a Step 5 instruction block: "Add accesssync_webhook_secret to your Wix Secrets Manager." Without this, every webhook fails HMAC verification. Add it before the events.js code block so operators see it in sequence.
NOVA
OB-25
Set CORE_ENGINE_URL on Railway Admin Hub Service
Quick Railway config — not code. Without this env var set, Step 5 shows a blank webhook URL in the events.js code block. Operators paste a broken URL into their Wix backend.
Daxx
P6
Verify events.js Field Paths Against Live Wix Event
Run a real test purchase on the HOG Wix site and log the full payload AccessSync receives. Confirm memberId, planId, orderId paths match what wix-adapter.js expects. Fix any mismatches. This is the only way to know the pipeline is correct.
NOVA + Daxx
Definition of Done
Daxx uses the owner PIN → location activates → maps one Wix plan to one Kisi group → adds events.js + webhook secret to HOG Wix backend → buys a test plan → member appears in Kisi within 10 seconds. This is the first end-to-end proof the system works.

4
Hardening + Security
Goal: Safe to open to real paying clients beyond internal testing
All paths · Pre-launch
OB-24
Protect Operator Signup Endpoints
Currently POST /operator/clients is fully public — anyone can create a client record. Options: invite token, Wix app install JWT, or rate limiting. Must be resolved before promoting the onboarding URL publicly.
NOVA
OB-43
End-to-End Validation Step in Onboarding
After wizard completes, run: (a) Kisi key valid ✓, (b) at least one plan mapping exists ✓, (c) optional test webhook fires ✓. Operator sees a checklist before "Account Created!" — confidence that the system is actually connected.
NOVA
OB-26
Dashboard Surfaces "Connect Kisi" CTA When Key is Missing
Operators who complete onboarding without a Kisi key currently have no recovery path. Dashboard must detect kisi_api_key = null and surface a prominent "Connect your Kisi account" call to action.
NOVA
G-06 + G-10
Failure Runbook + Kisi Schema Review
G-06: Document the optimistic error resolve risk in the failure runbook. G-10: NOVA reviews full Kisi API docs and confirms all schema assumptions (field names, endpoint behavior, pagination). Both are hard gates for commercial launch.
NOVA + Daxx
Definition of Done
A second operator (not Daxx) can complete onboarding using only the wizard — no admin intervention, no Railway console access — and have a working provisioning system within 15 minutes.
